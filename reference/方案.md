3\. 修改后的消息流程

3.1 App 启动时同步消息



所有端统一这样做：



App 打开

→ 检查登录状态

→ 读取 last\_message\_id / last\_sync\_time

→ 请求 /api/messages?after=xxx

→ 服务端返回新消息

→ StorageRuntime.saveMessages()

→ 更新消息中心



伪代码：



export class MessageService {

&#x20; constructor(

&#x20;   private api: ApiClient,

&#x20;   private storage: StorageRuntime,

&#x20; ) {}



&#x20; async syncMessages() {

&#x20;   const lastId = await this.storage.getSyncState('last\_message\_id')



&#x20;   const messages = await this.api.get('/messages', {

&#x20;     after: lastId,

&#x20;   })



&#x20;   await this.storage.saveMessages(messages)



&#x20;   if (messages.length > 0) {

&#x20;     await this.storage.setSyncState(

&#x20;       'last\_message\_id',

&#x20;       messages\[messages.length - 1].id,

&#x20;     )

&#x20;   }

&#x20; }



&#x20; async markRead(messageId: string) {

&#x20;   const readAt = Date.now()



&#x20;   await this.storage.markMessageRead(messageId, readAt)



&#x20;   await this.storage.enqueueSyncTask({

&#x20;     id: crypto.randomUUID(),

&#x20;     type: 'mark\_message\_read',

&#x20;     payload: { messageId, readAt },

&#x20;     createdAt: Date.now(),

&#x20;     retryCount: 0,

&#x20;   })

&#x20; }

}

class MessageKeepAliveService : Service() {



&#x20;   companion object {

&#x20;       const val ACTION\_START = "com.yourapp.keepalive.START"

&#x20;       const val ACTION\_STOP = "com.yourapp.keepalive.STOP"



&#x20;       private const val CHANNEL\_ID = "keep\_alive\_channel"

&#x20;       private const val NOTIFICATION\_ID = 1001



&#x20;       fun scheduleRestart(context: Context) {

&#x20;           val enabled = context.getSharedPreferences("keep\_alive", Context.MODE\_PRIVATE)

&#x20;               .getBoolean("enabled", false)



&#x20;           if (!enabled) return



&#x20;           val intent = Intent(context, RestartReceiver::class.java)



&#x20;           val pendingIntent = PendingIntent.getBroadcast(

&#x20;               context,

&#x20;               2001,

&#x20;               intent,

&#x20;               PendingIntent.FLAG\_UPDATE\_CURRENT or PendingIntent.FLAG\_IMMUTABLE

&#x20;           )



&#x20;           val alarmManager = context.getSystemService(Context.ALARM\_SERVICE) as AlarmManager



&#x20;           alarmManager.setAndAllowWhileIdle(

&#x20;               AlarmManager.RTC\_WAKEUP,

&#x20;               System.currentTimeMillis() + 5\_000,

&#x20;               pendingIntent

&#x20;           )

&#x20;       }

&#x20;   }



&#x20;   override fun onCreate() {

&#x20;       super.onCreate()

&#x20;       createChannel()

&#x20;   }



&#x20;   override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {

&#x20;       when (intent?.action) {

&#x20;       }

&#x20;   }



&#x20;   override fun onTaskRemoved(rootIntent: Intent?) {

&#x20;   }



&#x20;   override fun onDestroy() {

&#x20;       super.onDestroy()



&#x20;       SocketManager.stop()



&#x20;       val enabled = getSharedPreferences("keep\_alive", MODE\_PRIVATE)

&#x20;           .getBoolean("enabled", false)

5\. StorageRuntime 修改后的职责



因为 Android Service 不再写消息，本地存储只由前端业务层统一维护。



StorageRuntime 负责：

1\. 设置项

2\. 登录用户信息缓存

3\. 消息中心缓存

4\. 已读状态

5\. 同步游标

6\. 离线同步队列



不负责：



Android Service 后台收到消息时的写入



所以平台表可以改成：



平台	本地存储

Web	IndexedDB + localStorage

Android Tauri 前端	SQLite + Store + FS

iOS Tauri 前端	SQLite + Store + FS

Windows Tauri	SQLite + Store + FS



不再有：



Android Service Storage

AndroidMessageStore

AndroidSettingsStore



这两个模块可以删除。



6\. 数据一致性靠服务端补拉



由于 Android 后台 Service 不保存消息，本地消息中心的数据完整性依赖服务端同步。



所以服务端必须支持：



1\. 离线消息保存

2\. 按 last\_message\_id / last\_sync\_time 补拉

3\. ACK 和已读分离

4\. 多端消息状态同步



建议区分两个概念：



delivered / ack：

&#x20; 后台服务收到消息并确认“已到达设备”



read：

&#x20; 用户打开消息中心或点击消息后才算已读



也就是说 Android Service 收到消息时只发：



{

&#x20; "type": "ack",

&#x20; "messageId": "msg\_123"

}



但不代表已读。



用户进入消息中心后，前端再调用：



POST /api/messages/msg\_123/read



或批量：



POST /api/messages/read

8\. 调整后的最终方案总结



现在的方案变成：



服务端：

&#x20; 负责权威消息、离线消息、ACK、已读状态、同步接口



Web：

&#x20; 页面内 WebSocket

&#x20; IndexedDB/localStorage

&#x20; 不通知、不保活



Android：

&#x20; Tauri 前端负责业务和 StorageRuntime

&#x20; Kotlin Service 负责后台保活

&#x20; 常驻通知用于 Foreground Service

&#x20; 普通通知由 Kotlin Service 收到消息后直接弹

&#x20; START\_STICKY 尝试系统杀后恢复

&#x20; onTaskRemoved + AlarmManager 尝试划掉任务后拉起

&#x20; Service 不保存消息，不写数据库



Windows：

&#x20; Rust 后台 WebSocket

&#x20; 收到消息可写 StorageRuntime / SQLite

&#x20; Tauri notification 弹通知



iOS：

&#x20; 前台 WebSocket

&#x20; 后台不做 Android 式保活

&#x20; 后续需要可靠远程通知则接 APNs



StorageRuntime：

&#x20; 只服务于前端业务层

&#x20; 负责消息中心缓存、设置、同步状态、离线任务



一句话总结：



修改后 Android 原生 Service 只作为“后台消息感知与通知触发器”，不参与本地数据持久化。真正的消息记录、已读状态和本地缓存，统一由 App 打开后的前端业务层通过服务端同步并写入 StorageRuntime。
